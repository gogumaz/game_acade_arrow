## §1. 게임 개요 · 타깃 · 설치 환경

### 1.1 한 문장 정의

**얽힌 화살표 사슬 더미에서 지금 빠지는 사슬을 읽어 내 화살촉 방향으로 빼내고, 120초 안에 최대한 깊은 보드까지 나아가 최고 점수를 남기는 레버 조작 1인용 아케이드 퍼즐이다.**

### 1.2 핵심 플레이 루프

```text
① 읽는다 → ② 고른다 → ③ 당긴다 → ④ 갈린다 ──────→ ⑤ 바뀐다 ─┐
  안전수    레버 순환    버튼1       성공: 슬라이드 아웃      │
  탐색      포커스       진로 판정   + 점수·콤보·시간 회복    │
  (§3.3)    (§2.2)      (§3.3)      실패: 빨간 낙인          │
                                    + 하트 -1 + 시간 -3초    │
       └──── 보드를 비우면 다음 보드 ◄── 의존 관계 갱신 ◄─────┘
```

한 번의 입력이 항상 즉시 성공/실패로 판정되고, 그 결과가 다음 판단의 정보가 된다. 규칙 설명은 10초, 첫 성공은 10초 이내, 한 판은 약 120초다.

### 1.3 설계 기둥

| # | 기둥 | 게임 내 의미 | 근거 |
|---|---|---|---|
| 1 | **한 레버, 한 규칙** | 포커스 이동 + 당기기 외의 규칙을 코어에 넣지 않는다. 힌트조차 규칙이 아니라 보조다 | REF §2.4 |
| 2 | **읽힌다** | 막힘과 출구가 시각적으로 명확하고, 판정은 언제나 결정적이며 설명 가능하다 | docx §3 |
| 3 | **보이는 실수** | 잘못 고른 사슬은 빨갛게 남아 다음 판단의 단서가 된다. 실패를 숨기지 않는다 | REF §2.4, 영상 01:10~01:47 |
| 4 | **손맛이 있다** | 사슬이 자기 몸을 따라 화면 밖으로 빠져나가는 길이·굽힘 비례 연출과 소리 | docx §3, REF §8.1 |
| 5 | **욕심이 난다** | 빠른 연속 성공은 콤보와 시간 회복으로 갚아 주고, 성급한 오선택은 하트와 시간을 뺏는다 | docx §3 |
| 6 | **밀도가 곧 난이도** | 새 규칙 없이 사슬 수·길이·의존 깊이로만 난이도를 만든다. 저대비·미세 오브젝트로 만드는 인위적 난이도는 쓰지 않는다 | REF §2.4, docx §1.3 |
| 7 | **한 판 더가 짧다** | 결과 화면에서 재도전까지 5초 이내. 실패 원인을 한 문장으로 알려 준다 | docx §3 |

### 1.4 타깃과 설치 환경

| 항목 | 사양 |
|---|---|
| 주 고객 | 8~35세 캐주얼·가족·커플 방문객, 짧은 점수 경쟁을 원하는 반복 플레이어, 퍼즐 숙련자 |

설치 환경은 **D-1 확정 사항이며 docx의 32인치 세로형 터치 캐비닛 사양은 채택하지 않는다.** 채택하지 않은 하드웨어 항목과 사유는 부록 G에 기록한다.

## §2. 조작 체계 — 레버 + 2버튼

조작은 **레버(4방향) + 버튼 2개**가 전부다. 마우스·터치·소프트 키보드에 의존하는 조작은 어디에도 두지 않는다.

### 2.1 추상 입력과 매핑

| # | 추상 입력 | P1 물리 입력 | 개발 키 | 인게임 의미 |
|---|---|---|---|---|
| 1 | `UP` | 레버 위 | `W` | 포커스를 같은 열의 위쪽 사슬로 |
| 2 | `DOWN` | 레버 아래 | `S` | 포커스를 같은 열의 아래쪽 사슬로 |
| 3 | `LEFT` | 레버 왼쪽 | `A` | 포커스를 왼쪽 열로 |
| 4 | `RIGHT` | 레버 오른쪽 | `D` | 포커스를 오른쪽 열로 |
| 5 | **`BUTTON1`** | **우측 버튼** | `H` | **당기기** (제거 시도) |
| 6 | **`BUTTON2`** | **좌측 버튼** | `G` | **힌트** |
| 7 | `START` | START 버튼 | `F1` | 결제 후 런 시작, 결과 화면 건너뛰기 |
| 8 | `COIN` | 코인 셀렉터 펄스 | `F10` | 유료 크레딧 적립 |
| 9 | `SERVICE` | 코인 도어 내부 물리 SERVICE 키 | `F9` | 관리자 진입 (§11.1) |
| 10 | `RESERVED` | — | — | `[2차]` 예약 슬롯. 1차에서는 어떤 물리 입력에도 연결하지 않는다 |

- **P2 입력은 게임에서 무시**한다. 관리자 `INPUT TEST`에서만 별도 표시한다(§11.7).
- 버튼 역할은 `admin_page.md` §4.1과 일관된다 — 우측 버튼이 확정·실행, 좌측 버튼이 보조·취소다. 관리자 메뉴에서는 같은 물리 버튼이 `확정/실행`·`취소/뒤로`로 동작한다.
- 개발 키 `F9`는 출시 빌드에서 비활성화되고 물리 SERVICE 키만 남는다.
- WU-01 입력 어댑터의 액션명 `ROTATE`·`PLACE`·`ADMIN`·`DAILY`는 위 표의 `BUTTON1`·`BUTTON2`·`SERVICE`·`RESERVED`로 교체한다(§16.4).

### 2.2 사슬 순환 선택 알고리즘 (`확정`)

포커스는 항상 정확히 **1개 사슬** 위에 있다. 자유 커서는 두지 않는다(D-1 Q1-B).

**대표점.** 사슬의 대표점은 **화살촉 노드 `P(L-1)`** 이다. 사슬당 정확히 1개이고, 교차 금지(§3.1) 때문에 두 사슬의 대표점은 절대 겹치지 않는다.

**열 구조.** 대표점의 `x` 좌표가 같은 사슬들을 한 **열**로 묶는다. 사슬이 하나도 없는 `x`는 열로 세지 않는다.

| 입력 | 동작 | 타이브레이크 |
|---|---|---|
| `LEFT` / `RIGHT` | **열을 옮긴다.** 현재 열에서 왼쪽/오른쪽으로 가장 가까운 비어 있지 않은 열로 이동. 양 끝에서는 반대쪽 끝으로 **순환**한다 | 새 열 안에서는 **현재 `y`와 가장 가까운** 사슬을 잡는다. 위·아래 거리가 같으면 **위쪽(`y`가 작은 쪽)** |
| `UP` / `DOWN` | **같은 열 안에서** `y`가 더 작은/큰 사슬로 이동. 열의 양 끝에서는 같은 열 안에서 **순환**한다 | 열에 사슬이 1개뿐이면 이동하지 않고 거부음만 낸다 |

- **안전수를 타이브레이크에 쓰지 않는다.** 안전수 우선 순환은 포커스 이동만으로 정답을 노출시켜 퍼즐 자체를 무효화한다. docx의 "안전수 우선 대상 결정" 규칙은 이 사유로 미채택이다(부록 G).
- 보드 시작 시 초기 포커스는 **가장 왼쪽 열의 가장 아래쪽(`y` 최대) 사슬**이다. 참고 영상의 실제 플레이가 하단·가장자리부터 해체하는 순서를 따른다(REF 타임라인 00:07~00:30).
- 사슬 제거 직후 포커스는 **마지막 레버 입력 방향으로 한 번 이동한 결과**로 옮긴다. 그 방향에 사슬이 없으면 `RIGHT` → `DOWN` 순으로 대체 적용하고, 보드에 사슬이 1개 남으면 그 사슬을 잡는다.
- 포커스 대상 사슬이 제거되거나 상태가 바뀌어도 **포커스는 자동으로 튀지 않는다.** 위 규칙 외의 자동 이동은 없다.

**최악 조작 수 상한 (Q1-B 순환 피로 대응).**

보드 격자 가로 폭은 13열이므로(§3.1) 비어 있지 않은 열은 최대 13개이고, 생성 제약이 **한 열의 대표점을 8개 이하**로 묶는다(§6.3 3단계). 양방향 순환이므로 좌우 이동은 최악 `⌊13/2⌋ = 6`회, 상하 이동은 최악 `⌊8/2⌋ = 4`회다. 따라서 **임의 사슬 → 임의 사슬 최악 조작 수는 10회**다.

- 보드 최대 사슬 수는 40개(§6.2)이므로 참고 영상의 100개 규모 밀집은 발생하지 않는다. 순환 피로는 **보드 규모 상한 + 열 구조 + 홀드 반복**의 3중으로 억제한다.
- 최악 조작 수가 **12를 넘는 보드는 출시 차단**된다(§6.4 #7). 상한 10에 여유 2를 둔 값이다.
- 인수 항목 `CTL-004`가 이 상한을 판정한다.

## §3. 코어 규칙

본 절의 규칙은 참고 영상에서 `확인`된 사실을 사양으로 승격한 것이며, 레퍼런스 분석서가 `추정`으로 남긴 진로 판정·재선택 규칙은 여기서 **확정**된다(부록 B).

### 3.1 격자 좌표계와 점유

| 요소 | 정의 |
|---|---|
| 보드 격자 | **가로 13 × 세로 19 격자 점** (x = 0~12 좌→우, y = 0~18 상→하). 원점은 좌상단 |
| 격자 선분 | 인접한 두 격자 점을 잇는 길이 1의 수평 또는 수직 변. 사슬은 격자 선분 위에만 놓인다 |
| 점유 | 사슬이 지나는 모든 격자 선분과 그 선분의 양 끝 격자 점 |
| **선분 단위 배타 점유** | 하나의 격자 선분은 **최대 한 사슬만** 점유한다 |
| **교차 금지** | 서로 다른 두 사슬은 같은 격자 점도 공유하지 않는다. 사슬끼리 겹치거나 교차하는 배치는 생성 단계에서 금지한다(§6.3) |

교차 금지는 보드 밀도를 낮추는 제약이 아니라 **판정의 결정성을 보장하는 제약**이다. 두 사슬이 한 점을 공유하면 "누가 먼저 그 점을 비우는가"에 따라 진로 판정이 달라져 §3.3의 일괄 판정이 성립하지 않는다.

### 3.2 사슬 데이터 모델

| 항목 | 정의 |
|---|---|
| 사슬(chain) | 격자 점의 순서열 `P0, P1, ... , P(L-1)`. 이웃 점은 항상 인접하며 방향은 상·하·좌·우 4방향뿐이다 |
| **노드 수 L** | 사슬이 지나는 격자 점 수. **선분 수 = L − 1** |
| **화살촉(머리)** | 마지막 점 `P(L-1)`에 정확히 1개. 머리 방향 `d` = `P(L-1) − P(L-2)` |
| 꼬리 | 첫 점 `P0`. 화살촉이 없다 |
| **굽힘 수 B** | 진행 방향이 바뀌는 내부 점의 수. 직선 사슬은 `B = 0` |
| 최소 크기 | `L ≥ 2` (선분 1개 이상). 생성기의 실사용 하한은 `L = 3`(§6.2) |
| 제거 단위 | 사슬은 **통째로 한 단위**로 제거된다. 부분 제거·분할·회전은 없다 |
| 상태 | `정상` / `포커스` / `막힘(빨강)` / `제거 중` / `제거됨` 5종. 동시에 하나만 갖는다 |

`노드 수 L`·`굽힘 수 B`는 점수 공식(§5.1)의 입력이므로 데이터 모델의 필수 필드다.

### 3.3 진로 판정 (`확정`)

사슬을 당기면 사슬은 **자기 경로를 따라** 전진한다. 머리는 자기 방향 `d`로 직진해 보드 밖으로 나가고, 뒤따르는 점들은 앞 점이 지나간 자리를 그대로 밟는다. 따라서 새로 쓸고 지나가는 공간은 **머리 앞의 직선 진로뿐**이다.

**진로 `R(S)` 정의**
`R(S)` = 머리 `P(L-1)`에서 방향 `d`로 한 칸씩 나아가며 만나는 **격자 점의 열**과 그 사이 **격자 선분의 합집합**. 보드 경계를 벗어날 때까지 이어진다. 머리 자신의 점은 포함하지 않는다.

**막힘 조건**
`R(S)`에 포함된 격자 점 또는 격자 선분 중 하나라도 **다른 사슬 T가 점유**하고 있으면 `S`는 막힘이다. 그 밖의 경우는 전부 안전수다.

| 규칙 | 내용 |
|---|---|
| 판정 시점 | **선택 즉시 일괄 판정.** 전진 중 충돌 판정이 아니다. 막힌 사슬은 1픽셀도 움직이지 않는다 |
| 자기 몸 | 사슬 자신의 선분은 판정 대상이 아니다. 자기 몸은 이미 지나간 자리다 |
| 보드 밖 | 진로가 보드 경계를 만나면 그 지점에서 판정을 끝낸다. 보드 밖에는 블로커가 없다 |
| 부분 이동 중인 사슬 | 제거 애니메이션이 진행 중인 사슬(`제거 중`)은 **`제거됨` 플래그가 서기 전까지 원래 점유를 그대로 유지하며 여전히 블로커다.** 점유 해제는 §3.4-3의 시점에 한 번에 이루어지고, 그 전까지 다른 사슬의 판정은 이 사슬이 아직 있는 것으로 계산한다. 시각 상태와 논리 상태는 원자적으로 전환한다 |
| 결정성 | 같은 보드 상태·같은 사슬이면 판정 결과는 항상 같다. 난수·시간·입력 순서에 의존하지 않는다 |

**영상 01:10 케이스 재현.** 중앙 좌측의 ㄱ자 사슬은 화살촉이 `←`(서쪽)를 향한다. 머리에서 서쪽으로 이어지는 진로 `R` 위의 어느 격자 점을 **다른 사슬의 세로 선분**이 점유하고 있었다. 세로 선분은 수평 진로와 선분을 공유하지는 않지만 그 **격자 점을 점유**하므로 위 막힘 조건에 걸린다. 결과는 영상과 같이 사슬이 제자리에서 빨간색으로 바뀌고 하트가 1개 줄어드는 것이다. 격자 점을 포함하지 않고 선분만으로 판정하면 이 케이스가 "안전수"로 오판되므로, **점 + 선분 합집합 판정이 필수 요건**이다.

**안전수(safe move) 정의.** 현재 보드 상태에서 위 막힘 조건에 걸리지 않는 사슬. 안전수는 **솔버(§6.3)가 계산한 결과와 실시간 판정 결과가 완전히 일치**해야 한다. 불일치는 출시 차단 조건이며(§6.4) 인수 항목 `GEN-403`으로 판정한다.

### 3.4 제거 — 경로 추종 슬라이드 아웃

1. 판정이 안전수면 사슬은 즉시 `제거 중` 상태가 되고 입력 잠금이 걸린다(§2.6).
2. 사슬은 **자기 경로를 그대로 따라** 머리 방향으로 미끄러진다. 직선 이탈이 아니라 경로 추종이며, 굽은 사슬은 굽은 형태를 유지한 채 자기 몸을 통과해 나간다.
3. 꼬리 `P0`가 보드 경계를 넘어가는 순간 `제거됨` 플래그가 서고, 그 시점에 점유가 해제된다.
4. 이동 시간 = `기본 0.18초 + 선분 수 × 0.022초`, 상한 0.75초 **`[운영 설정]`**(§9.2). 긴 사슬일수록 길게 빠져나가 손맛과 관전성을 만든다.
5. 제거된 사슬이 비운 선분·점은 다음 판정부터 즉시 자유 공간이 된다.

### 3.5 막힘 처리와 실패 비용

| 항목 | 규칙 |
|---|---|
| 표시 | 막힌 사슬은 즉시 **막힘색(빨강)** 으로 바뀌고 짧게 좌우 진동한다. 블로커 방향으로 플래시를 1회 보낸다(§9.2) |
| **잔존** | 빨간 표시는 자동으로 사라지지 않고 **그 사슬이 제거될 때까지 유지**된다. 실수는 보드 위에 기록으로 남아 다음 판단의 단서가 된다 |
| **재선택** | 빨간 사슬은 언제든 다시 선택할 수 있다. 진로를 막던 사슬이 제거되어 진로가 열리면 **정상적으로 제거**되며 표시도 함께 사라진다 |
| **하트** | **−1** |
| **시간** | **−3초** (§4.3) |
| **콤보** | **즉시 0으로 초기화** (배율 1.0 복귀, §5.2) |
| **점수** | **직접 차감 없음.** 실패의 비용은 하트·시간·콤보로만 지불한다 |
| **반복 실패 보호** | 마지막 실패 이후 **보드 상태(사슬 집합)가 전혀 변하지 않았다면**, 같은 사슬을 다시 당겨도 하트·시간·콤보를 다시 깎지 않고 거부음과 블로커 플래시만 낸다. 상태가 한 번이라도 바뀌면 보호가 풀린다 |

반복 실패 보호는 docx §5.3의 "불리한 상태 변경 시 입력을 취소하고 하트를 차감하지 않는다"는 원칙을 레버 조작에 맞게 확장한 것이다. 같은 정보 상태에서 같은 오답을 반복하는 것은 새로운 실수가 아니라 조작 미숙이므로 비용을 이중으로 물리지 않는다.

### 3.6 보드 클리어와 런 종료

| 조건 | 결과 |
|---|---|
| 보드의 모든 사슬 제거 | **보드 클리어.** 클리어 정산(§5.4) → 다음 보드 생성·전환(§4.2) |
| 하트 0 | **런 종료** → 컨티뉴 제안(§4.5) |
| 남은 시간 0 | **런 종료** → 컨티뉴 제안(§4.5) |
| 컨티뉴 미사용 또는 불가 | 결과 화면 → 랭킹 등록 → 어트랙트(§4.7) |

하트와 시간은 **동등한 종료 조건**이다. 어느 쪽이든 먼저 0에 닿으면 런이 끝난다.

### 3.7 처리 순서와 결정성

한 번의 당기기 입력은 항상 아래 순서로 처리된다. 순서를 바꾸면 점수·시간 수지가 달라지므로 구현은 이 순서를 고정한다.

```text
① 입력 수신 (버튼1)         → 포커스 사슬 S 확정, 입력 잠금
② 진로 판정 (§3.3)          → 안전수 / 막힘
③-A 안전수 → 제거 개시      → S 를 '제거 중'으로. 점유는 아직 유지
③-B 막힘  → 실패 처리       → 하트 -1, 시간 -3초, 콤보 0, 빨간 표시
④ 시간 수지 반영 (§4.3)     → 성공 시 회복 가산 (상한 적용) / 실패 시 감산
⑤ 점수·콤보 반영 (§5.1·5.2) → 성공 시 기본점 × 콤보 배율 가산
⑥ 제거 완료·점유 해제       → 꼬리가 보드 밖으로 나간 시점, 원자적 전환
⑦ 의존 관계 갱신            → 전체 사슬의 안전수 여부 재계산
⑧ 클리어·종료 검사 (§3.6)   → 보드 클리어 / 런 종료 / 계속
⑨ 입력 잠금 해제 · 버퍼 소비 → 대기 중인 버퍼 입력이 있으면 ①로
```

- ④와 ⑤ 사이에는 어떤 상태 변화도 끼어들지 않는다. 시간 회복이 먼저, 점수가 나중이다.
- ⑦의 재계산은 보드 전체를 대상으로 하며 부분 갱신 최적화를 쓰더라도 **전체 재계산과 같은 결과**를 내야 한다.
- 같은 시드·같은 입력 순서·같은 입력 시각이면 최종 점수까지 완전히 재현된다(§6.6).

### 3.8 정답 없는 상태 금지

| 규칙 | 내용 |
|---|---|
| 출시 콘텐츠 | 안전수가 0개인 보드 상태를 **금지**한다. 어떤 제거 순서를 밟아도 교착에 빠지지 않는 보드만 출시한다(§6.3 솔버 전수 탐색) |
| 런타임 감지 | 그럼에도 안전수 0이 감지되면 **즉시 무상 힌트를 띄우지 않고**, 보드에서 가장 의존 깊이가 얕은 사슬 1개를 자동으로 제거해 진행을 복구한다. 이때 점수·콤보·시간은 변동시키지 않는다 |
| 기록 | 자동 보정 발생 시 시드·보드 상태·보정 대상을 `error_YYYY-MM-DD.log`에 기록하고 관리자 OVERVIEW에 1회 경고를 표시한다(§12.3) |
| 원인 제거 | 자동 보정은 응급 처치이며 재발 시드는 생성기 회귀 대상이다. 보정 발생률 목표는 **0건 / 10만 보드** |

### 4.3 시간 수지

런 타이머는 성공으로 늘고 실패로 줄어든다. 회복은 **잘하는 사람이 조금 더 오래 플레이하되 회전율은 지켜지는** 크기로 설계했다.

| # | 항목 | 공장 기본값 | 조정 범위 | 초안 근거 |
|---|---|---|---|---|
| **N2** | 성공 시 시간 회복 **`[운영 설정]`** | **사슬 기본 0.25초 + 의존 깊이 1당 0.08초** | 기본 0~0.5초 / 깊이 계수 0~0.2초 | docx §8.1 |
| **N2b** | 1회 회복 상한 **`[운영 설정]`** | **0.9초** | 0~1.2초 | docx 부록 B(시간 회복 상한 라인당 0.9초 / 허용 0~1.2초) |
| **N3** | 실패 시 시간 페널티 **`[운영 설정]`** | **−3초** | 0~−5초 | docx §8.1·부록 B |
| N3b | 실패 시 하트 | −1 (`확정`) | — | REF `확인`(01:10 하트 3→2) · docx §5.2 |

**적용 규칙**

1. 회복량 = `min(0.25 + 0.08 × 해당 사슬의 의존 깊이, 0.9)`. 의존 깊이는 §6.1의 정의를 쓴다.
2. 회복은 §3.7의 ④ 단계에서 가산하며, **런 타이머의 상한은 세션 시간(120초)** 이다. 초과분은 버린다.
3. 페널티는 같은 ④ 단계에서 감산하며, 하한은 0초다. 0에 닿는 순간 런이 종료된다(§3.6).
4. 회복과 페널티가 같은 입력에서 동시에 발생하는 경우는 없다. 한 입력은 성공이거나 실패다.
5. 보드 클리어·전환 연출 중에도 타이머는 계속 흐른다. 멈추는 것은 미니 튜토리얼과 안전 중지뿐이다.

**세션 예산 검산 (R17 대조).** §6.2 구간표의 목표 클리어 시간과 위 회복량이 120초 안에서 성립하는지 확인한다. 평균 라인 의존 깊이는 구간 최대 의존 깊이 중앙값의 절반으로 근사했다.

| 구간 | 사슬 수(중앙) | 최대 의존 깊이(중앙) | 평균 라인 깊이 | 회복/사슬 | 보드 회복 | 목표 클리어 | **순 소모** | 누적 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 1~3 워밍업 | 9 | 3 | 1.5 | 0.37초 | 3.3초 | 11.7초 | **8.4초** | 25.2초 |
| 4~6 리듬 | 15 | 5.5 | 2.8 | 0.47초 | 7.1초 | 16.0초 | **8.9초** | 51.9초 |
| 7~9 압박 | 21.5 | 9 | 4.5 | 0.61초 | 13.1초 | 23.0초 | **9.9초** | 81.6초 |
| 10~12 마스터 | 29 | 13 | 6.5 | 0.77초 | 22.3초 | 32.5초 | **10.2초** | 112.2초 |
| 13+ 엔드리스 | 34 | 16 | 8.0 | 0.89초 | 30.3초 | 38.0초 | **7.7초** | 119.9초 |

- 목표 시간을 정확히 지키는 숙련자는 **120초에 12~13보드**에 도달한다. 이것이 1차 밸런스의 기준선이다.
- 목표의 2배 시간이 걸리는 초심자는 **5~6보드**에서 시간이 소진된다. 실패 1회당 추가로 3초를 잃는다.
- 회복 상한 0.9초는 **의존 깊이 9 이상인 사슬**에서 작동한다(`0.25 + 0.08 × 9 = 0.97`). 압박 구간부터 일부, 엔드리스 구간에서는 다수의 사슬이 상한에 걸리며 이 구간의 회복이 목표 시간의 약 80%를 되돌려 준다. 상한이 없으면 깊은 보드에서 타이머가 사실상 무한해져 회전율이 무너진다.

### 4.4 종료 조건

**하트 0 또는 시간 0이면 런이 끝난다.** 두 조건은 동등하며 어느 하나가 먼저 성립하는 즉시 판정한다.

| 상황 | 처리 |
|---|---|
| 하트가 0이 된 입력 | 그 입력의 실패 연출을 끝까지 재생한 뒤 CONTINUE 화면으로 |
| 시간이 0이 된 순간 | 진행 중인 제거 애니메이션은 끝까지 재생하고 **그 사슬의 점수는 인정**한 뒤 CONTINUE 화면으로 |
| 두 조건 동시 성립 | 하트 0을 먼저 표시하고 시간 0을 이어서 표시한다. 결과는 같다 |
| 보드 클리어와 시간 0 동시 | **클리어를 먼저 정산**한다(§5.4). 클리어 정산 점수는 인정하고 다음 보드는 시작하지 않는다 |

### 4.6 1크레딧 흐름과 목표 시간

| 단계 | 목표 시간 | 플레이어 경험 | 시스템 처리 |
|---|---|---|---|
| 어트랙트 | 반복 | 규칙과 고득점 장면을 구경 | 15초 데모, 오늘의 1위, 조작 1문장 |
| 결제·시작 | 5~10초 | 코인 투입 후 START | 크레딧 확인·차감, 신규 여부 판정 |

## §5. 점수 · 콤보 · 등급 · 랭킹

### 5.1 점수 공식

사슬 1개를 성공적으로 제거할 때마다 아래 식으로 점수를 얻는다.

```text
기본점 = 100 + 20 × max(L - 3, 0) + 40 × B + 60 × D
획득점 = floor(기본점 × 콤보 배율)

  L = 노드 수 (§3.2)          — 사슬이 지나는 격자 점 수, 선분 수 + 1
  B = 굽힘 수 (§3.2)          — 방향이 바뀌는 내부 점 수
  D = 의존 깊이 (§6.1)        — 이 사슬을 빼기 전에 먼저 빼야 했던 선행 사슬의 최장 연쇄 길이
```

| 항 | 의미 | 설계 의도 |
|---|---|---|
| 100 | 기본 보상 | 어떤 사슬이든 성공은 보상한다 |
| `20 × max(L−3, 0)` | 길이 가산 | 긴 사슬은 슬라이드 아웃이 길고 판독도 어렵다. `L < 3`은 음수 가산을 막기 위해 0으로 하한 처리한다 |
| `40 × B` | 굽힘 가산 | 굽은 사슬은 진로를 읽기 어렵고 제거 연출도 화려하다 |
| `60 × D` | 의존 깊이 가산 | **논리 난이도의 주축.** 순서를 읽어 낸 대가를 가장 크게 지불한다 |

- 의존 깊이 `D`는 **제거 시점에 다시 계산하지 않는다.** 보드 생성 시 확정된 값(§6.3 5단계)을 사용해 같은 시드에서 점수가 완전히 재현되게 한다.
- 획득점은 소수점 버림(`floor`)한다. 표시 점수와 저장 점수는 항상 정수다.

### 5.2 콤보

| 항목 | 규칙 |
|---|---|
| 상승 조건 | 성공 후 **2.2초 이내**에 다음 성공 |
| 배율 | 1.0에서 시작해 **+0.15씩 상승**, **최대 2.5배** (10단계에서 상한) |
| 판정 기준 시각 | 직전 성공의 **제거 완료 시각**(§3.7 ⑥). 애니메이션이 긴 사슬이 불리해지지 않게 한다 |
| 리셋 | 실패(§3.5) · 2.2초 초과 · 컨티뉴 · 보드 전환 **아님** |
| 보드 전환 | 콤보는 **보드를 넘어 유지**된다. 마지막 사슬과 다음 보드 첫 사슬 사이에도 2.2초 창이 적용된다 |
| 표시 | 배율이 2 이상일 때만 크게 노출한다(§8.2) |

보드 전환에서 콤보를 유지하는 것은 "보드 마지막 사슬을 빨리 빼고 다음 보드로 달려드는" 흐름을 만들기 위한 결정이다. 대신 전환 연출 0.8초가 2.2초 창을 소모하므로 실제 여유는 1.4초다.

### 5.3 힌트 감점

| 항목 | 규칙 |
|---|---|
| 적용 대상 | 힌트를 **1회 이상** 사용한 보드에서 얻은 **사슬 점수 합계**(§5.1 기본점 × 콤보 배율의 보드 내 합). 클리어 정산(§5.4)의 시간·하트 보너스는 감점 대상이 아니다 |
| 계수 | **횟수당 누적** — 1회 × 0.8, 2회 × 0.6, 3회 × 0.4 … (`HINT SCORE PENALTY` −20%/회, `HINT PENALTY CAP` −60% 하한 → 최저 × 0.4). 수치·근거는 §7.2 N5a·N5a′ (2026-08-15 최종 승인 결정) |
| 퍼펙트 | 힌트를 쓴 보드는 **퍼펙트 보너스 무효** |
| 적용 시점 | 보드 클리어 정산 시 일괄 적용. 인게임 점수 표시는 감점 전 값을 보여 주고, 보드 클리어 순간 감점 후 값으로 정정한다 |

### 5.4 보드 클리어 정산과 퍼펙트

```text
클리어 정산 = 남은 시간(초, 버림) × 100  +  남은 하트 × 1,500
퍼펙트 보너스 = 5,000   (해당 보드에서 오입력 0회 AND 힌트 0회)
보드 최종 = floor(사슬 점수 합계 × 힌트 계수) + 클리어 정산 + 퍼펙트 보너스
           (힌트 계수 = max(1 − 0.2 × 힌트 횟수, 0.4), §5.3·§7.2. 힌트를 썼으면 퍼펙트 보너스는 0)
```

- `남은 시간`은 **런 타이머의 잔여 시간**이다. 빨리 클리어할수록 이후 모든 보드의 정산이 함께 커지므로, 초반 속도가 런 전체의 점수를 좌우한다.
- `남은 하트`는 정산 시점의 하트 수다. 하트는 보드마다 회복되지 않으므로 무실수 플레이의 가치가 런 내내 누적된다.
- 퍼펙트는 **보드 단위** 판정이다. 런 전체 무실수 여부와 무관하다.
- 런 종료 시점에 클리어하지 못한 보드는 정산하지 않는다. 그 보드에서 이미 얻은 사슬 점수는 유지한다.

## §6. 스테이지 생성 · 솔버 · 난이도

보드는 **전량 절차 생성 + 솔버 검증**으로 만든다(D-1 Q6). 수제 보드 데이터는 1차 범위에 없으며 관리자도 사슬을 직접 배치하지 않고 **파라미터만** 조정한다(§11.4).

### 6.1 난이도 축

| # | 축 | 정량 정의 | 튜닝 방향 |
|---|---|---|---|
| 1 | **사슬 수** | 보드의 사슬 개수 `N` | 인지 부하는 늘지만 이 축 단독으로 난이도를 올리지 않는다 |
| 2 | **의존 깊이** | 사슬 `X`의 깊이 `D(X)` = 진로를 막는 사슬이 없으면 0, 있으면 `1 + max(막는 사슬들의 깊이)`. 보드 값은 전 사슬의 최댓값 | **논리 난이도의 주축.** 구간 진행의 1차 조절 손잡이 |
| 3 | **분기 폭** | 보드 시작 시점의 안전수 개수(= 깊이 0인 사슬 수) | 적을수록 정답 압박, 많을수록 속도 선택의 자유 |
| 4 | **유사 후보** | 모양·화살촉 방향이 비슷하지만 막힌 사슬의 비율 | 시각 함정은 §9.1 대비 기준 안에서만 사용 |
| 5 | **경로 복잡도** | 평균 노드 수 `L`·평균 굽힘 수 `B` | 제거 연출 길이와 점수 가치를 함께 올린다 |
| 6 | **포커스 밀도** | 순환 선택에서 목표 사슬까지 필요한 **평균 조작 수**(§2.2) | 난이도 점수와 **분리**해 품질 제한으로만 관리. 상한 초과 보드는 폐기 |
| 7 | **시간 압박** | 남은 시간 대비 예상 소요 입력 수 | 후반 구간에서 상승, 1~3 워밍업에서는 완화 |

**축 6은 난이도가 아니라 품질 제한이다.** 논리 난이도(축 2·3)를 먼저 올리고 시각·조작 밀도는 뒤에서 완만하게 따라가게 한다. 조작을 어렵게 만들어 얻은 난이도는 §1.3 기둥 6 위반이다.

### 6.2 구간별 보드 범위

| # | 구간 | 사슬 수 | 초기 안전수(분기 폭) | 최대 의존 깊이 | 목표 클리어 시간 |
|---|---|---|---|---|---|
| **N8a** | 1~3 워밍업 | 6~12 | 3~5 | 2~4 | 8~15초 |
| **N8b** | 4~6 리듬 | 12~18 | 2~4 | 4~7 | 12~20초 |
| **N8c** | 7~9 압박 | 18~25 | 2~3 | 7~11 | 18~28초 |
| **N8d** | 10~12 마스터 | 24~34 | 1~2 | 10~16 | 25~40초 |
| **N8e** | 13+ 엔드리스 | 28~40 | 1~3 | 12~20 | 적응형(§6.5) |

- 전 구간 **`[운영 설정]`**. 조정 범위는 사슬 수 4~60, 안전수 1~10, 의존 깊이 1~30, 목표 시간 5~90초.
- 초안 근거: docx §9.2 보드 범위표 5구간 + docx 부록 A 예시 런 사양(기믹 열 제외) + REF §5.3 난이도 곡선.
- 보드 격자는 전 구간 **13×19 고정**(§3.1)이다. 밀도는 격자가 아니라 사슬 수·길이로 조절한다.
- **난이도는 보드 번호에 대해 단조 증가**한다. 구간 안에서도 사슬 수·의존 깊이가 구간 하한에서 상한으로 선형 보간된다.
- 13보드 이후는 구간 파라미터가 상한에 닿은 상태에서 §6.5 적응 정책만으로 조절된다. **파라미터 포화 시 사슬 수·깊이를 더 올리지 않고**, 유사 후보 비율(축 4)과 경로 복잡도(축 5)만 상한 안에서 올린다. 보드 수에 상한이 없으므로 파라미터에도 상한이 필요하다.
- 위 목표 클리어 시간이 §4.3 시간 수지와 120초 안에서 성립함은 §4.3의 검산표로 확인했다.

### 6.3 생성 파이프라인

**채택 알고리즘: 정답 순서 역생성 → 역순 배치.** 아래 6단계를 그대로 구현한다.

| 단계 | 처리 | 실패 시 |
|---|---|---|
| **1. 난이도 벡터 선택** | 보드 번호 → §6.2 구간 → `(사슬 수 N, 최대 의존 깊이 Dmax, 분기 폭 F, 길이 분포)` 결정. 적응 보정(§6.5) 반영 | — |
| **2. 정답 순서 역생성·역순 배치** | 제거 순서 `s1 → s2 → ... → sN`을 먼저 정한 뒤 **역순(`sN` 먼저, `s1` 마지막)** 으로 격자에 배치한다. `s_i`를 놓을 때 이미 놓인 것은 `s_(i+1)...s_N`뿐이므로, **`R(s_i)`가 그들과 겹치지 않는지만 검사**하면 `s1...sN` 순서가 유효한 해법임이 구성적으로 보장된다 | 해당 사슬만 재배치(최대 64회) |
| **3. 제약 검증** | 선분 배타 점유·교차 금지(§3.1), 화살촉 가시성, 사슬 간 최소 시각 간격, **한 열의 대표점 8개 이하**, **포커스 순환 최악 조작 수 ≤ 12**(§2.2) | 3단계 위반 시 2단계로 복귀 |
| **4. 솔버 전수 탐색** | 모든 도달 가능 상태를 탐색해 ① 무해법 ② 순환 교착(안전수 0 도달) ③ 과도한 단일 정답 구간(연속 5회 이상 안전수 1개)을 걸러낸다. 동시에 **초기 안전수 수와 최대 의존 깊이를 실측**해 목표 벡터와 대조한다 | 재시드(§6.7) |
| **5. 봇 측정·깊이 확정** | 결정적 봇으로 예상 해결 시간·오입력 가능성·프레임 부하를 측정하고 난이도 점수를 산출한다. **각 사슬의 의존 깊이 `D`를 확정해 보드 데이터에 저장**한다(§5.1이 이 값을 쓴다) | 목표 시간의 1.8배 초과 시 재시드 |
| **6. 번들 기록** | 시드·난이도 벡터·해법 순서 해시·측정값을 **로컬 보드 번들**에 기록한다. 같은 시드는 언제나 같은 보드를 만든다 | — |

- 2단계의 역생성이 **1안으로 확정 채택**된 알고리즘이다.
- 기각안 ①: 무작위 배치 후 솔버로 걸러내기 — 사슬 20개 이상 고밀도에서 해법 존재 확률이 급격히 떨어져 재시드 비용이 실시간 생성에 부적합하다. 기각안 ②: 수제 보드 300개 — 콘텐츠 제작량이 1차 범위를 넘고 무제한 보드 진행(§4.2)과 맞지 않는다(`[2차]`).
- 6단계의 **서명·원격 검증은 1차 범위 밖**이며 `[2차]` 콘텐츠 서명 번들로 분류한다(§7.3). 오프라인 로컬 운영에서는 로컬 해시 대조로 충분하다.
- 생성은 **다음 보드 전환 연출(0.8초) 동안 백그라운드로 선행 수행**한다. 현재 보드 진행 중에 다음 보드를 미리 생성해 대기시킨다.

### 6.6 시드와 재현성

- 런 시작 시 **런 시드**를 1개 뽑고, 보드 시드는 `해시(런 시드, 보드 번호, 난이도 벡터)`로 유도한다.
- **같은 시드 + 같은 난이도 벡터 → 항상 같은 배치**다. 생성기는 시스템 시각·프레임 시간·입력 타이밍을 참조하지 않는다.
- 적응 난이도가 켜져 있으면 난이도 벡터가 플레이 결과에 따라 달라지므로 런 전체는 재현되지 않는다. **보드 단위 재현성은 항상 성립**하며, 관리자 테스트 플레이(§11.6)는 벡터를 직접 지정해 완전 재현한다.
- 오류 로그에는 런 시드·보드 번호·난이도 벡터를 함께 남겨 현장에서 보드를 재현할 수 있게 한다(§12.3).

|---|---|---|

| 2 | 파라미터 완화: 사슬 수 −2, 최대 의존 깊이 −1 후 재시도 | **8회** (완화는 최대 2회 누적) |
| 3 | **폴백**: 직전 구간의 마지막 검증 통과 보드를 재사용 | 무제한 |
| 4 | 폴백까지 실패 | 런을 중단하지 않고 §6.2 워밍업 하한 벡터로 보드를 만든다. 이 경로는 인수 항목 `GEN-406`으로 검증한다 |

## §10. 코인 · 크레딧 운영

코인·크레딧 계층은 게임 장르와 무관하므로 `admin_page.md` §7·§8의 규칙을 **그대로 재사용**한다. 본 절은 재사용 선언과 본 게임 고유의 차감 시점만 규정한다.

### 10.1 게임당 코인 C

| # | 수치 | 공장 기본값 | 조정 범위 | 초안 근거 |
|---|---|---|---|---|
| **N11a** | `COINS PER PLAY` (C) **`[운영 설정]`** | **1** | 1~9 | `admin_page.md` §8.1 |
| **N11b** | `CONTINUE COINS` **`[운영 설정]`** | **1** | 1~9 | §4.5 N4c. 시작보다 싸게 하려면 C를 2 이상으로 설정 |
| **N11c** | `COIN UNIT PRICE` (코인 1개의 금액) **`[운영 설정]`** | **미설정 → 관리자가 설치 시 결정** (설정 전 임시 표시값 1,000원) | 100~5,000원 | 1코인의 금액은 기기가 놓이는 매장의 코인 셀렉터·정책에 따르므로 **기획서가 정하지 않고 관리자가 결정한다**(2026-08-15 최종 승인 결정). `admin_page.md` §7.2 `ESTIMATED GROSS` 산출에만 사용되는 참고값 |

`C`는 시작·컨티뉴 같은 **1회 행동의 크레딧 비용**이다(`admin_page.md` §8.3). 소매가는 `코인 1개 금액 × C`로 결정된다 — 예: 500원 코인 기구에서 `C = 3`이면 1,500원, 1,000원 코인 기구에서 `C = 1`이면 1,000원. **본서는 원화 가격을 직접 고정하지 않는다.** `COIN UNIT PRICE`가 미설정이면 관리자 진입 시 OVERVIEW에 `▲ COIN UNIT PRICE 미설정` 경고를 표시하고 `ESTIMATED GROSS`를 숨긴다(`admin_page.md` §7.2 "단가 설정이 없으면 숨긴다" 규칙 재사용). 게임 플레이에는 영향이 없다.

### 10.2 차감 시점

| 행동 | 차감 | 시점 |
|---|---|---|
| 런 시작 | `C` | START 입력이 유효 판정된 직후, 미니 튜토리얼 진입 **전** |
| 컨티뉴 | `CONTINUE COINS` | 컨티뉴 확정 입력 직후, 보드 복귀 **전** |
| 관리자 테스트 플레이 | **차감 없음** | 크레딧·통계·랭킹에 일절 영향 없음 |
| P2 참가 | — | 2인 플레이 미채택(§14.3). 해당 차감 경로 자체를 두지 않는다 |

차감 후 게임 진입에 실패하면 크레딧을 **원복**하고 `credit_log.csv`에 원복 사유를 남긴다.

### 10.3 크레딧 상한

유료 크레딧 최대 **99**, 이벤트 크레딧 최대 **5**는 고정값이며 설정 대상이 아니다(`admin_page.md` §8.1). 이벤트 시작 잔액은 0이고 관리자 지급으로만 늘어나며 재시작 시 0으로 초기화된다.

### 10.4 혼합 결제 금지

- 이벤트 크레딧만으로 전체 `C`를 낼 수 있으면 **EVENT만** 사용한다.
- EVENT가 부족하면 EVENT와 PAID를 **섞지 않고** PAID만으로 전체 `C`를 결제한다.
- 둘 다 부족하면 결제하지 않고 거부음을 낸다.
- 인수 항목 `CRD-603`이 판정한다 (`admin_page.md` ADM-103 승계).

### 10.5 통계와 날짜 롤오버

`admin_page.md` §7.1의 10개 지표와 §7.2의 매출성 미터 6개를 **그대로 재사용**한다(부록 A). 본 게임 고유의 집계 규칙은 다음과 같다.

| 규칙 | 내용 |
|---|---|
| 유료 플레이 +1 | 유료 크레딧으로 **런이 실제 시작**된 시점(미니 튜토리얼 진입 포함) |
| 컨티뉴 +1 | 컨티뉴 1회당 +1. 2인 개념이 없으므로 언제나 +1이다 |

## §11. 관리자 페이지

관리자 페이지는 `admin_page.md` v2.0의 운영 사양을 **원칙적으로 그대로 승계**한다. 본 절은 ① 승계 선언 ② 본 게임에 맞춰 치환한 그룹 ③ 신설한 `GAME PARAMETERS`만 기술한다. 항목 단위 전수 대조는 부록 A에 있다.

### 11.1 진입과 보안

| 환경 | 진입 방식 | 정책 |
|---|---|---|
| 개발 빌드 | `F9` | 메인/어트랙트에서만 허용 |
| **출시 기기** | **코인 도어 내부 물리 SERVICE 키 단독** | Serial 입력으로만 허용 (`admin_page.md` §2.2) |

- **PIN 입력 화면을 두지 않는다.** docx §15.1의 "PIN + 물리 서비스 키" 병용은 **미채택**이다. `admin_page.md` §2.2가 정한 물리 SERVICE 키 단독 체계가 진입 보안의 기준이며, 역할별 인증 분리는 `[2차]`다. 관리자 화면 어디에도 숫자 입력 인증 절차가 없다.
- 플레이·컨티뉴·이름 입력·결과 정산 중에는 진입 요청을 무시한다(§2.7).
- 진입 시 처리 순서, 5분 유휴 자동 복귀, 미저장 작업 보호, `admin_enter` 감사 로그는 `admin_page.md` §3.1을 그대로 따른다.
- 조작은 **P1 레버 + 두 버튼만으로** 전 기능이 가능해야 한다. 홀드 반복 250ms/100ms, 큰 수치 필드의 2초 홀드 5배 가속도 그대로다(`admin_page.md` §4.1).
- 관리자 화면에서 START·게임 조작은 무효지만 **코인 입력은 정상 적립**한다.

### 11.5 저장 검증

파라미터 저장은 아래 검증을 **전부 통과해야** 실제 데이터에 반영된다.

| 구분 | 규칙 | 처리 |
|---|---|---|
| 오류 | 각 필드가 §11.4의 조정 범위를 벗어남 | 저장·테스트 불가 |
| 오류 | 구간표가 단조성을 위반 (뒤 구간의 사슬 수·의존 깊이가 앞 구간보다 작음) | 저장·테스트 불가 |
| **오류** | **저장될 파라미터로 각 구간 대표 보드를 생성했을 때 솔버가 통과하지 못함** (해법 0개·순환 교착·목표 시간 1.8배 초과 중 하나) | **저장·테스트 불가** |
| 오류 | 등급 임계가 내림차순이 아님 (S+ ≤ S 등) | 저장·테스트 불가 |
| 경고 | 초기 하트가 1 또는 6~9 | 재확인 후 저장 가능 (회전율 경고) |
| 경고 | `TIME GAIN CAP` 1.0초 초과 | 재확인 후 저장 가능 (회전율 경고) |
| 경고 | 세션 예산 검산(§4.3)에서 숙련자 도달 보드가 8 미만 또는 20 초과 | 재확인 후 저장 가능 |

- **솔버 게이트가 핵심이다.** 관리자 편집으로 클리어 불가능한 보드가 생성되는 경로를 원천 차단한다. 검증용 대표 보드는 5구간 × 3시드 = 15보드이며, 검증 시간 상한은 3초다.
- 오류가 여러 개면 전체 목록을 보여 준다. 경고 저장은 `H` 2초 홀드. 저장 전 이전 값을 `.bak`에 남긴다 (`admin_page.md` §9.4).

### 11.6 테스트 플레이

- 편집 중인 파라미터로 **크레딧 없이** 런을 실행한다. 구간·시드를 직접 지정해 완전 재현할 수 있다(§6.6).
- 유료·이벤트 통계, 랭킹, 점수 분포 표본, 크레딧에 **일절 집계하지 않는다**(`admin_page.md` §9.5).
- 컨티뉴를 차단한다. 클리어·런 종료·`G` 2초 홀드로 `GAME PARAMETERS`로 복귀한다.
- 테스트 중 들어온 실제 코인 펄스는 유료 크레딧에 정상 적립한다.
- 결과로 도달 보드, 보드별 클리어 시간, 오입력 수, 최종 점수, 등급을 임시 표시한다.

## §12. 저장 · 복구 · 오류

### 12.1 저장 파일

`admin_page.md` §11.1의 파일 구성을 승계하되, 이전 게임의 스테이지 데이터 파일을 본 게임의 파라미터·랭킹 파일로 치환한다.

| **`params.csv`** | **`GAME PARAMETERS` 전량** (세션·시간·난이도 구간표·힌트·점수·등급·랭킹) + `PARAM_DATA_VERSION` | 최신 + `.bak` | **`stages.csv` 치환** |

| `machine.json` | 기기 ID, 빌드, I/O 보드·OS 정보 | 최신 | 보존 |

- Electron은 실행 파일 기준 `./log/`를 사용한다. 브라우저 개발 모드는 `localStorage`, 저장 불가 환경은 세션 메모리를 쓴다.
- `PARAM_DATA_VERSION`이 공장 데이터 버전과 다르면 저장된 편집분을 적용하지 않고 새 공장값을 사용한다. 폐기 전 날짜가 붙은 백업을 남기고 `OVERVIEW`에 1회 경고한다 (`admin_page.md` §11.4 규칙 승계).
- 인코딩은 UTF-8, 날짜는 ISO 8601을 쓴다.

### 12.2 안전 쓰기

`admin_page.md` §11.3의 5단계 절차를 그대로 사용한다 — ① `.tmp` 기록 → ② 기록·스키마 검증 → ③ 본 파일을 `.bak`으로 이동 → ④ `.tmp`를 본 파일명으로 변경 → ⑤ 본 파일 재개봉 검증. WU-01에 이미 구현되어 있다(§16.2).

모든 쓰기는 Electron 메인 프로세스의 **단일 큐**에서 순차 처리한다. 전원 차단 중 매출 카운터·크레딧 손실 목표는 **0건**이다.

### 12.3 오류와 자동 복구

| 오류 | 화면 메시지 | 처리 |
|---|---|---|
| 치명 오류 1회 | `SYSTEM ERROR` | 날짜별 로그 기록 → 5초 후 자동 재실행 |
| 60초 내 치명 오류 3회 | `SERVICE REQUIRED` | 자동 재실행 중지, 유료 플레이 차단 |
| 설정·파라미터 저장 실패 | `SAVE FAILED · 저장 경로 확인` | 관리자 화면 유지, 재시도·저장소 테스트 제공 |
| CSV 손상·백업 복구 성공 | `BACKUP RESTORED` | 내용 확인 후 계속 |
| 본 파일·백업 모두 손상 | `FACTORY DATA LOADED` | 진단·제한 운영 |
| Serial 연결 해제 | `I/O DISCONNECTED` | 1초 간격 재연결, 10회 실패 시 `SERVICE REQUIRED` |
| 코인 입력 고정 / 디스크 부족 | `COIN INPUT STUCK` / `STORAGE LOW` | 입력 테스트 안내 / 로그 정리 안내, 차단 기준 확인 |
| 시간 변경 감지 | `CLOCK CHANGED` | 감사 로그 + 경고 |
| **보드 생성 폴백** | 화면 표시 없음 | 시드·벡터를 로그에 기록, `OVERVIEW`에 24시간 누계 표시 (§6.7) |
| **안전수 0 자동 보정** | 화면 표시 없음 | 시드·보드 상태를 로그에 기록, `OVERVIEW` 경고 1회 (§3.8) |
| 서비스 호출·도어 열림 | `SAFE PAUSE` | **런 타이머 정지.** 원인 해소 후 3초 카운트다운 뒤 재개 |

오류 메시지는 문제·영향·다음 행동 3요소를 포함한다(부록 E).

### 12.4 유료 플레이 차단 기준

아래 상태에서는 메인으로 복귀하더라도 유료 게임 시작을 차단한다 (`admin_page.md` §12.3 승계).

- Serial I/O 미연결로 코인·조작 입력을 신뢰할 수 없음
- 설정·통계 파일을 어떤 백엔드에도 저장할 수 없음 (메모리 백엔드 강등 포함)
- 60초 내 치명 오류 3회 발생
- 유료 크레딧 차감 로그 기록 실패 반복
- **`params.csv`가 손상되어 공장값·백업 어느 쪽으로도 복구되지 않음**

이미 들어온 유료 크레딧은 화면과 메모리에 유지하고 복구 후 사용할 수 있도록 우선 저장한다.

### 12.5 오프라인 동작 보장

- **인터넷 연결 없이** 결제 입력, 스탠더드 런, 보드 생성·솔버 검증, 로컬 랭킹, 관리자 메뉴, 진단, 감사 로그가 전부 동작한다. 네트워크를 전제로 하는 기능(원격 콘텐츠 갱신, 서버 랭킹, 텔레메트리 대시보드, 원격 진단)은 1차 범위에 **없다**(§14.2).
- 시각 동기화도 서버에 의존하지 않는다. OS 로컬 시각을 쓰고 역행·중복 롤오버를 감사 로그로 감지한다(§10.5).

## §16. 개발 환경

### 16.1 스택 (WU-01 재사용 확정)

D-1 Q10에 따라 기존 WU-01 산출물을 그대로 재사용한다. 새 엔진·언어를 도입하지 않는다.

| 계층 | 채택 | 비고 |
|---|---|---|
| 데스크톱 셸 | **Electron 43** | 키오스크 전체화면, 안전 쓰기, 자동 복구가 이미 구현됨 |
| 렌더링·씬 | **Phaser 4** | 2D 라인 렌더링과 씬 전환에 충분 |
| 언어 | **TypeScript 5.6** (`strict`) | — |
| 번들러 | **Vite 5** | — |
| 테스트 | **Vitest 3** | WU-01 회귀 스위트 유지 |
| 린트·포맷 | **ESLint 9 + Prettier 3** | — |
| 패키징 | **electron-builder** (`win portable` / `linux tar.gz`) | Ubuntu 통합은 `[보류]`(§17)이나 스크립트는 이미 양쪽을 지원 |

docx §18.1의 Godot 4.x 권장 아키텍처는 **채택하지 않는다.** 기존 스캐폴드·입력 어댑터·안전 쓰기·persist 계층이 이미 검증돼 있고, 엔진 교체는 D-1 Q10 결정에 반한다.

### 16.2 폴더 구조

| 경로 | 역할 | 상태 |
|---|---|---|
| `electron/main.cjs` · `preload.cjs` · `safe-write.cjs` | 메인 프로세스, IPC, 안전 쓰기 5단계 | WU-01 구현 완료 (§12.2) |

| `src/core/{grid,chain,puzzle,score,generator,solver}.ts` | **퍼즐 코어 — 렌더와 분리한 결정적 모듈** | WU-02·WU-08 신설 |
| `src/core/{settings,stats,credits,params,ranking}.ts` | 운영 데이터 | WU-04·WU-05 신설 |

## §17. `[보류]` 외부 항목

`[보류]`는 **외부 하드웨어·환경이 확정되기 전에는 값을 정할 수 없는 4종에만** 사용한다. 게임 규칙·수치·운영 항목에는 `[보류]`가 하나도 없다. 4종 모두 어댑터·플레이스홀더로 1차 구현을 막지 않는다(§14.5).

| # | 항목 | `[보류]`인 이유 | 확정 전 처리 | 확정 시 영향 |
|---|---|---|---|---|
| 1 | **`[보류]` Serial I/O 보드** | 포트·패킷 구조·입력 코드·펄스 폭·디바운스·재연결 정책이 보드 제작사 사양에 종속된다 | `InputAdapter` 계약(WU-01)에 키보드 어댑터를 끼워 전 기능을 검증한다. `SERIAL I/O TEST` 화면은 미연결 상태까지 구현한다 | 조작·코인·SERVICE 입력 경로 전체 |
| 2 | **`[보류]` 물리 SERVICE 키** | 단발/토글 신호 방식과 코인 도어 내 위치가 캐비닛 설계에 종속된다 | 개발 `F9`로 같은 진입 경로를 검증하고, 출시 빌드에서 `F9`를 비활성화한다 | 관리자 진입 보안 (§11.1) |
| 3 | **`[보류]` Ubuntu 24.04 키오스크 통합** | X11/Wayland 선택, 자동 실행, 절전, OS 종료 권한이 운영 OS 결정에 종속된다 | Windows 키오스크로 1차를 검증한다. `linux tar.gz` 패키징 스크립트는 이미 존재한다 (§16.1) | `SYSTEM ACTIONS`의 재부팅·종료 (§11.7) |
| 4 | **`[보류]` 최종 UI·아트·사운드 자산** | 실제 폰트·아이콘·효과음·BGM은 외주·제작 일정에 종속된다 | §9의 팔레트·타이밍·규격을 만족하는 플레이스홀더로 인수 판정을 수행한다 | 시각·청각 품질. 규격은 이미 확정 |

**남발 금지.** docx에서 온 서명·원격 검증·콘텐츠 배포는 외부 하드웨어 문제가 아니라 **범위 결정**이므로 `[보류]`가 아니라 `[2차]`로 분류한다(§14.2).
