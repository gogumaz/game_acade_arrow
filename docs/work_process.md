## 0. 프로세스 원칙

모든 작업 단위(기획 사이클 D-n, 구현 유닛 WU-nn)는 하네스의 4단계를 **독립적으로** 통과한다.

| 단계 | 담당 | 산출물 | 게이트 |
|---|---|---|---|
| Phase 1 — Q&A 착수 | qa-interviewer / qa-intake | `00_qa_intake.md` | 이해도 90%+ · 치명적 열린 질문 0 · 사용자 승인 |
| Phase 2 — 계획 | task-planner / work-planning | `01_work_plan.md` | 사용자 승인 |
| Phase 3 — 실행 | task-executor / work-execution | 문서·코드 + `02_execution_log.md` | 계획 완료 기준 충족 |
| Phase 4 — 독립 검증 | quality-verifier | `03_quality_report.md` | PASS (FIX/REDO는 원인 단계로 회귀) |

- 작업 기록은 `_workspace/<번호>_<단위명>/`에 저장한다.
- **코드 작성은 구현 유닛(WU)의 Phase 3에서만 한다.** 기획 사이클(D-n)에서는 코드를 만들지 않는다.
- 구현 유닛은 **`arrow_out_arcade_gdd_v1_0.md`의 절만 근거로 삼는다.** 레퍼런스 분석 기획서의 `추정`·`미확정`·`제안` 항목은 D-2에서 확정되었으므로(같은 문서 부록 B) 원문 상태 표기를 다시 사실로 인용하지 않는다.
- 검증 FIX는 해당 단위 안에서 수정하고, REDO는 원인 단계(Q&A/계획/실행)로 되돌린다.
- 범위 밖 요구사항이 발견되면 해당 단위를 멈추지 말고 **새 Q&A 사이클로 분리**한다.
- 이 저장소의 이전 기획(8×20 테트로미노, `docs/_archive/`)은 다른 게임의 산출물이며 새 게임의 근거로 쓰지 않는다. 단 게임 무관 계층(관리자 운영 기준, WU-01 기반 코드)은 재사용 대상이다.

## 4. 2차 유닛 (D-1 Q7·Q8 확정 반영)

2차 대상은 기획서 §14.2에 항목명과 한 줄 정의로 확정되어 있다: **특수 사슬 4종 · 데일리 챌린지 · 타임 어택 · 매장 토너먼트 · 키즈 프리플레이 · 테마 패키지 · 수제 보드 세트 · USB 로그 내보내기 · `play_log.csv` · 콘텐츠 서명 번들 · 원격 콘텐츠 갱신 · 관리자 PIN·역할 분리 · 다국어 음성 · 캐비닛 RGB 조명 · 관전자/매장 이벤트 확장.**

**제외 확정**(1차·2차 모두 하지 않음, 기획서 §14.3): 2인 플레이(협력·대전) · 되돌리기(UNDO) · 인게임 재시작 버튼 · 카드/QR 결제 · 서버 텔레메트리 · 광고·확률형 상품.

유닛 번호(WU-10~) 부여와 범위 분해는 **2차 착수 사이클의 Q&A(Phase 1)** 에서 수행한다. 착수 조건은 기획서 §14.4의 "2차 착수 조건"이다.

## 5. 공통 규칙

1. **워크스페이스 명명:** 기획 사이클 `_workspace/6_arrow_gdd/`(D-1은 `d1_qa/`, D-2는 `d2_gdd/`), 구현 `_workspace/7_arrow_wu01/` ~ `7_arrow_wu09/`, 2차 `8_arrow_wu10/`~.
2. **커밋 단위:** 단위의 Phase 4 PASS 후 커밋. 메시지에 단위 번호를 붙인다 (`D-2: ...`, `WU-02: ...`).
3. **회귀 방지:** 구현 유닛의 Phase 4는 이전 유닛의 테스트를 스모크로 재실행한다 (`npm run test`).
4. **[보류] 항목:** Serial I/O 보드·물리 SERVICE 키·Ubuntu 통합·최종 자산은 어댑터/플레이스홀더로 1차를 막지 않는다 (기획서 §17 · `admin_page.md` §19와 동일 원칙).
5. **순서 조정:** 의존 관계 안에서 유닛 순서는 계획 단계에서 조정 가능.
6. **레퍼런스 게임 자산 비복제:** 원작 명칭·아트·UI·문구를 복제하지 않는다 (기획서 문서 헤더 선언).
7. **참조 코드:** `game_acade_puzzle`은 관리자·크레딧·저장 계층의 참조 구현으로만 읽기 전용 사용. 테트로미노 규칙 코드는 참조하지 않는다.
8. **원본 docx 수정 금지:** `docs/상용_아케이드게임_상세기획서_ARROW_OUT_v1.0.docx`는 읽기 전용 입력 근거다. 수정·삭제·이동하지 않으며, 작업에는 추출본(`_workspace/6_arrow_gdd/d2_gdd/input_docx_extracted.md`)만 사용한다.
