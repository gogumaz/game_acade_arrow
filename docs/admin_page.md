## 0. 문서 목적과 판정 기준

본 문서는 오락실 업주·현장 기사·개발팀이 같은 기준으로 관리자 페이지를 제작하고 검수하기 위한 **출시 목표 운영 사양서**다. 기존 관리자 문서의 모든 기능을 포함하며, 실제 영업 기기에 필요한 매출 보호, 오조작 방지, 장애 진단, 데이터 복구, 변경 이력과 현장 운영 절차를 추가한다.

관리자 페이지는 일반 플레이어용 옵션 화면이 아니다. 코인 도어 안쪽의 서비스 패널을 사용하는 **Operator/Service Menu**이며, 다음 세 가지를 최우선으로 한다.

1. 영업 중 발생한 코인과 운영 데이터를 잃지 않는다.
2. 조이스틱과 두 개 버튼만으로 3분 안에 주요 점검을 끝낸다.
3. 위험한 변경은 실수로 실행되지 않으며, 실행 결과를 추적할 수 있다.

### 0.1 상태 표기

| 표기 | 의미 |
|---|---|
| **[구현]** | 프로토타입 v0.5.0 코드에서 동작 확인 가능한 항목 |
| **[출시 P0]** | 상용 기기 출고 전에 반드시 구현·검증할 항목 |
| **[운영 P1]** | 첫 현장 운영 또는 업데이트에서 제공할 개선 항목 |
| **[보류]** | I/O 보드·OS·유통 정책 확정 후 결정할 항목 |

### 0.2 핵심 성공 기준

| 목표 | 출시 판정 기준 |
|---|---|
| 접근 통제 | 플레이 중 진입 불가, 출시 빌드에서 F9 단독 진입 불가 |
| 빠른 운영 | 진입 후 3회 이하 조작으로 오늘 플레이 수·기기 상태 확인 |
| 매출 보호 | 관리자·테스트 플레이 중 들어온 코인도 유실 없이 유료 크레딧에 반영 |
| 안전한 변경 | 설정·스테이지 저장 성공/실패가 화면에 명확히 표시 |
| 오조작 방지 | 초기화·복원·종료는 별도 확인 단계와 감사 로그 필요 |
| 장애 대응 | 입력, 사운드, 화면, 저장소, Serial I/O를 현장에서 개별 진단 가능 |
| 복구 가능성 | 저장 중 전원 차단 후 정상 파일 또는 `.bak`으로 부팅 복구 |
| 운영 추적 | 매출성 지표와 이벤트 지급·사용·설정 변경을 날짜와 함께 조회 가능 |

## 1. 아케이드 운영 문법

### 1.1 설계 원칙

- **물리 입력 우선:** 마우스, 터치, 소프트 키보드에 의존하지 않는다.
- **짧고 얕은 구조:** 메뉴 깊이는 최대 3단계로 제한하고 현재 위치를 항상 표시한다.
- **10-foot 가독성:** 1920×1080 화면을 선 채로 읽을 수 있는 크기와 대비를 유지한다.
- **상태보다 행동을 먼저:** `SAVE`, `TEST`, `RESET`, `BACK`의 결과와 위험도를 즉시 구분한다.
- **매장 소음 대응:** 선택·확정·거부·오류 효과음은 서로 명확히 다르며 시각 피드백을 병행한다.
- **수익과 재미의 분리:** 코인/플레이 통계와 스테이지 난이도 데이터는 별도 영역에서 관리한다.
- **안전한 기본값:** 알 수 없는 데이터나 장치 오류가 발생하면 공장값 또는 마지막 정상 백업으로 복귀한다.
- **현장 설명 가능성:** 모든 수치에는 단위, 집계 기준, 마지막 갱신 시각을 제공한다.

### 1.2 플레이 화면과 다른 시각 언어

- 게임의 네온 연출을 최소화하고 어두운 회색 서비스 메뉴 톤을 사용한다.
- 장식보다 정보 밀도를 우선하되, 선택 행과 위험 행은 색상뿐 아니라 기호로도 구분한다.
- 정상은 청록, 주의는 노랑, 오류·파괴 작업은 빨강, 읽기 전용은 회색으로 표시한다.
- 지속 애니메이션은 선택 커서와 연결 상태 표시만 허용한다.
- 관리자 화면에서는 랭킹용 8자리 0 패딩 대신 통계에 천 단위 구분자를 사용한다.

## 2. 사용자와 권한

### 2.1 운영 역할

| 역할 | 주요 업무 | 권한 |
|---|---|---|
| 업주/매니저 | 매출·플레이 확인, 가격·볼륨 설정, 이벤트 크레딧 지급 | 일반 운영 + 통계 초기화 |
| 현장 기사 | 입력·I/O·사운드·화면·저장소 점검, 로그 확인 | 유지보수 + 재시작 |
| 개발/QA | 키보드 입력, 스테이지 편집, 테스트 플레이 | 개발 빌드 전체 기능 |

첫 출시에서는 물리 서비스 키를 가진 사용자를 단일 관리자 역할로 취급한다. 역할별 PIN 분리는 **[운영 P1]**이며, 위험 작업의 감사 로그는 역할 분리와 무관하게 **[출시 P0]**다.

### 2.2 진입 보안

| 환경 | 진입 방식 | 정책 |
|---|---|---|
| 개발 빌드 | F9 | **[구현]** 메인/어트랙트에서만 허용 |
| 출시 기기 | 코인 도어 내부 물리 SERVICE 키 | **[출시 P0]** Serial 입력으로만 허용 |
| 현장 정비 | SERVICE 키 + 필요 시 4자리 PIN | **[운영 P1]** 점주 설정으로 PIN 사용 여부 선택 |

- 플레이, 컨티뉴, 이름 입력, 결과 정산 중에는 진입 요청을 무시한다.
- 출시 빌드에서는 F9를 비활성화하거나 개발 플래그가 있을 때만 허용한다.
- 관리자 진입 시 활성 플레이 세션이 없어야 하며, 크레딧 잔액은 유지한다.
- 관리자 화면에서 START·게임 조작은 무효지만, **코인 입력은 유실 방지를 위해 정상 적립**한다.
- 5분간 입력이 없으면 저장 상태를 확인한 뒤 메인/어트랙트로 자동 복귀한다. 미저장 작업 사본이 있으면 자동 복귀하지 않고 경고음을 낸다. **[출시 P0]**

## 3. 진입·종료와 화면 흐름

```text
MAIN / ATTRACT
    └─ SERVICE 키
        └─ ADMIN HOME
            ├─ SALES & CREDITS
            ├─ MACHINE SETTINGS
            ├─ STAGE SETTINGS
            │   └─ STAGE LIST
            │       └─ STAGE EDIT
            │           ├─ MAP EDIT
            │           └─ TEST PLAY ──┐
            ├─ MAINTENANCE             │
            ├─ DATA & LOGS             │
            └─ EXIT ───────────────────┴─> MAIN
```

### 3.1 진입 시 처리 순서

1. 활성 플레이·결과·이름 입력 상태가 아닌지 확인한다.
2. 저장된 날짜와 OS 날짜를 비교해 오늘 통계 롤오버를 처리한다.
3. 저장소, 입력 장치, Serial I/O, 사운드 초기화 상태를 검사한다.
4. 코인·이벤트 잔액과 미완료 저장 작업을 확인한다.
5. `ADMIN HOME`을 표시하고 `admin_enter` 감사 로그를 남긴다. **[출시 P0]**

### 3.2 종료 정책

- `EXIT & SAVE` 선택 시 모든 예약 저장을 즉시 완료한 후 메인으로 복귀한다.
- 저장 성공 시 `SAVED · YYYY-MM-DD HH:MM:SS`를 최소 1초 표시한다.
- 저장 실패 시 관리자 화면을 닫지 않고 오류 원인·저장 경로·재시도 메뉴를 표시한다.
- 좌측 버튼으로 루트에서 나가려 할 때 변경 사항이 없으면 즉시 복귀한다.
- 미저장 작업이 있으면 `SAVE / DISCARD / CANCEL` 3가지 선택을 제공한다. **[출시 P0]**

## 4. 공통 조작과 UI 규칙

### 4.1 물리 입력 매핑

| 동작 | 아케이드 입력 | 개발 키 | 동작 규칙 |
|---|---|---|---|
| 이전 행 | P1 조이스틱 위 | W | 읽기 전용 행은 건너뜀 |
| 다음 행 | P1 조이스틱 아래 | S | 끝에서 처음으로 순환 |
| 값 감소/이전 탭 | P1 조이스틱 왼쪽 | A | 범위 끝에서는 더 움직이지 않음 |
| 값 증가/다음 탭 | P1 조이스틱 오른쪽 | D | 범위 끝에서는 더 움직이지 않음 |
| 확정/실행 | 우측 버튼 | H | 선택, 저장, 확인 |
| 취소/뒤로 | 좌측 버튼 | G | 한 단계 뒤로, 확인 취소 |
| 관리자 진입 | 물리 SERVICE 키 | F9 | 메인/어트랙트에서만 |

- 방향 홀드는 250ms 후 100ms 간격으로 반복한다. **[구현]**
- 숫자 범위가 큰 필드는 2초 이상 홀드하면 5배 단위로 가속한다. **[출시 P0]**
- P2 입력은 관리자 화면에서 무시하되 INPUT TEST에서는 별도로 표시한다.
- 모든 조작에 선택음·확정음·거부음을 제공하며 사운드 0에서도 시각 피드백은 유지한다.

### 4.2 공통 화면 레이아웃

```text
┌────────────────────────────────────────────────────────────────────┐
│ ADMIN > SECTION > PAGE                  2026-08-14 14:32  ● ONLINE │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│  > SELECTED ITEM                           VALUE / STATUS           │
│    ITEM 2                                  1                       │
│    ITEM 3                                  NORMAL                  │
│                                                                    │
│                                           상세 설명·단위·영향 범위 │
├────────────────────────────────────────────────────────────────────┤
│ W/S 이동 · A/D 변경 · H 확정 · G 뒤로       SAVED 14:31:52        │
└────────────────────────────────────────────────────────────────────┘
```

| 영역 | 사양 |
|---|---|
| 헤더 | 경로, 날짜·시간, 저장소/I/O 종합 상태 |
| 메뉴 | 좌측 60%, 선택 행 `>`와 반전 표시 |
| 상세 패널 | 우측 40%, 설명·범위·기본값·현재 영향 |
| 푸터 | 현재 화면에서 유효한 조작만 표시 |
| 토스트 | 성공 2.5초, 경고 3초, 오류는 사용자가 확인할 때까지 유지 |

### 4.3 값과 상태 표현

- 수치는 반드시 단위를 표시한다: `80 %`, `20 SEC`, `1 CREDIT`.
- 변경 전/후가 중요한 값은 `1 → 2` 형식으로 표시한다.
- 즉시 반영 설정은 `LIVE`, 다음 게임부터 반영은 `NEXT GAME`, 재시작 필요는 `RESTART REQUIRED`를 붙인다.
- 마지막 저장 상태는 `SAVED`, `SAVING`, `UNSAVED`, `SAVE FAILED` 중 하나로 항상 표시한다.
- 색맹 대응을 위해 정상 `●`, 경고 `▲`, 오류 `×`, 읽기 전용 `—` 기호를 함께 사용한다.

## 6. OVERVIEW — 운영 대시보드

### 6.1 화면 목적

업주가 관리자 진입 직후 기기의 영업 상태를 10초 안에 판단하는 화면이다. 조작 없이 핵심 정보를 읽을 수 있어야 한다.

### 6.2 표시 항목

| 카드 | 표시 내용 | 갱신 |
|---|---|---|
| 오늘 영업 | 오늘 유료 플레이, 이벤트 플레이, 컨티뉴 | 실시간 |
| 크레딧 | PAID 잔액, EVENT 잔액, 오늘 코인 펄스 | 실시간 |
| 기기 상태 | 입력/I/O, 저장소, 사운드, 전체화면 | 1초 |
| 콘텐츠 | 앱 버전, 스테이지 데이터 v4, 마지막 설정 저장 | 진입/저장 시 |
| 최근 장애 | 마지막 오류 시각과 요약, 24시간 오류 횟수 | 진입/오류 시 |

### 6.3 종합 상태 규칙

| 상태 | 조건 | 표시 |
|---|---|---|
| `● READY` | 필수 장치 연결, 저장 성공, 치명 오류 없음 | 청록 |
| `▲ CHECK` | 백업 복구 사용, 시간 변경, 로그 보존 초과, 선택 장치 경고 | 노랑 |
| `× SERVICE REQUIRED` | Serial 미연결, 저장 불가, 60초 내 3회 치명 오류 | 빨강 |

`SERVICE REQUIRED` 상태에서는 유료 플레이 진입을 막고 관리자·진단·코인 보전만 허용한다.

## 7. SALES & CREDITS — 운영 통계와 크레딧

### 7.1 현행 통계 정의

| 지표 | 집계 기준 | 초기화 |
|---|---|---|
| `TOTAL PAID PLAY COUNT` | 유료 크레딧으로 실제 게임 화면 진입 시 +1 | 유료 통계 초기화 |
| `TODAY PAID PLAY COUNT` | 위 항목 중 OS 로컬 날짜가 오늘인 수 | 날짜 변경/유료 통계 초기화 |
| `PAID CONTINUE COUNT` | 유료 C 사용 컨티뉴 1회당 플레이어별 +1 | 유료 통계 초기화 |
| `EVENT PLAY COUNT` | 이벤트 크레딧으로 실제 게임 화면 진입 시 +1 | 이벤트 통계 초기화 |
| `TODAY EVENT PLAY COUNT` | 위 항목 중 오늘 발생 수 | 날짜 변경/이벤트 통계 초기화 |
| `EVENT CONTINUE COUNT` | 이벤트 C 사용 컨티뉴 1회당 플레이어별 +1 | 이벤트 통계 초기화 |
| `EVENT CREDIT BALANCE` | 현재 사용 가능한 이벤트 크레딧, 0~5 | 지급·사용·재시작·이벤트 초기화 |
| `TOTAL EVENT CREDIT GRANTED` | 관리자가 지급한 누적 이벤트 크레딧 | 이벤트 통계 초기화 |
| `TOTAL EVENT CREDIT USED` | 실제 결제에 사용된 누적 이벤트 크레딧 | 이벤트 통계 초기화 |
| `TODAY EVENT CREDIT USED` | 오늘 사용된 이벤트 크레딧 | 날짜 변경/이벤트 통계 초기화 |

집계 세부 규칙은 다음과 같다.

- P2 중간 참가는 새 플레이 수로 집계하지 않는다.
- 처음부터 2인은 세션 기준으로 집계하되, 결제 소스가 다르면 소스별 1회씩 기록한다.
- 컨티뉴는 플레이어별 C 사용 1회당 +1이며 두 명이면 +2다.
- 대전 재대전은 새 플레이 +1이며 컨티뉴에는 포함하지 않는다.
- 관리자 테스트 플레이는 유료·이벤트 통계, 랭킹, 크레딧에 일절 집계하지 않는다.

### 7.2 매출성 지표 보강

현행 `PLAY COUNT`만으로는 가격 변경 이력과 무료 이벤트를 분리한 실제 매출을 계산할 수 없다. 상용판에는 다음 하드웨어·결제 미터를 추가한다. **[출시 P0]**

| 지표 | 정의 | 비고 |
|---|---|---|
| `COIN PULSE TOTAL` | I/O 보드에서 정상 수신한 누적 코인 펄스 | 삭제 불가 수명 미터 권장 |
| `COIN PULSE TODAY` | 오늘 수신한 코인 펄스 | 날짜 롤오버 |
| `PAID CREDIT GRANTED` | 코인 펄스로 생성된 유료 크레딧 | 펄스 환산값 포함 |
| `PAID CREDIT USED` | 시작·참가·컨티뉴·재대전에 사용된 유료 크레딧 | 크레딧 로그 합계와 일치 |
| `SERVICE CREDIT GRANTED` | 정비용 수동 크레딧 | 일반 코인과 분리 |
| `ESTIMATED GROSS` | 코인 펄스 × 운영자가 설정한 코인 단가 | 참고값, 회계 원장 아님 |

- 영구 코인 미터는 일반 통계 초기화로 지우지 않는다.
- 가격이 변경되면 변경 시각, 이전값, 새값을 감사 로그에 기록한다.
- `ESTIMATED GROSS`는 단가 설정이 없으면 숨긴다.
- 환불·코인 걸림 등 현금함 실제 금액과 차이가 날 수 있음을 화면에 표기한다.

### 7.3 이벤트 크레딧 지급

- `EVENT CREDIT GRANT`에서 H 1회당 이벤트 크레딧 +1, 최대 5다. **[구현]**
- 지급 즉시 코인 효과음, 잔액 변화, 지급 성공 토스트를 표시한다.
- 최대치에서는 값이 증가하지 않으며 거부음과 `MAX 5`를 표시한다.
- 지급자, 시각, 지급 전/후 잔액을 `credit_log.csv`와 감사 로그에 기록한다. 감사 로그는 **[출시 P0]**다.
- 이벤트 크레딧은 재시작 시 0으로 초기화하며 누적 지급·사용 통계는 유지한다.

### 7.4 통계 초기화

| 작업 | 초기화 대상 | 유지 대상 |
|---|---|---|
| `RESET PAID STATISTICS` | 누적/오늘 유료 플레이, 유료 컨티뉴 | PAID 잔액, 영구 코인 미터, 이벤트 데이터 |
| `RESET EVENT STATISTICS` | 이벤트 플레이/컨티뉴, 지급·사용, 오늘 사용, EVENT 잔액 | 유료 데이터, 영구 코인 미터 |

실행 절차:

1. H 1회: 대상 항목과 현재값을 보여주는 확인 화면을 연다.
2. H를 2초간 유지: 초기화 직전 백업과 감사 로그를 생성한다.
3. 성공: 모든 대상값을 0으로 표시하고 즉시 저장한다.
4. 실패: 기존값을 유지하고 `RESET FAILED`를 표시한다.
5. G: 언제든 취소한다.

현행 구현은 같은 행에서 H를 두 번 누르는 방식이다. 출시판은 홀드 확인, 대상값 표시, 백업 생성을 추가한다.

### 8.3 게임당 코인 C

- C는 시작, P2 참가, 컨티뉴, 재대전 같은 1회 행동의 크레딧 비용이다.
- 이벤트 크레딧만으로 전체 C를 낼 수 있으면 EVENT만 사용한다.
- EVENT가 부족하면 EVENT+PAID를 섞지 않고 PAID만으로 전체 C를 결제한다.
- 값 변경은 이미 진행 중인 결제/세션에는 영향을 주지 않고 다음 결제부터 적용한다.
- UI 상세 패널에 `1P START = 1C`, `2P START = 각 플레이어 1C` 예시를 표시한다.

### 8.4 초기 하트

- 다음 신규 1인·협력 게임부터 적용한다.
- 진행 중 세션, 컨티뉴 직전 세션, 테스트 플레이에는 소급 적용하지 않는다.
- 1~2는 회전율이 짧아질 수 있고 7~9는 영업 회전율이 길어질 수 있음을 경고한다. **[출시 P0]**

### 8.5 저장 규칙

- 값 변경 후 800ms 디바운스로 CSV 저장한다. **[구현]**
- 화면에는 `UNSAVED → SAVING → SAVED` 상태를 표시한다. **[출시 P0]**
- EXIT 시 예약 저장을 취소하지 말고 즉시 `saveAll()`을 완료한다.

## 9. STAGE SETTINGS — 스테이지 운영 콘텐츠

`STAGE SETTINGS`는 **목록 → 수치 편집 → 맵 편집**의 3단 구조다. 라이브 데이터가 아닌 작업 사본에서 편집하고, 검증과 저장을 통과한 경우에만 실제 데이터에 반영한다.

### 9.1 스테이지 목록

- 12개 스테이지를 한 화면에 표시한다.
- 각 행에는 이름, 1인/협력 목표, 배치 시간, 점수 배율, 잠식 사용 여부를 표시한다.
- 하단에 `[ RESET ALL STAGES ]`, `[ BACK ]`을 둔다.
- W/S로 이동, H로 선택, G로 뒤로 간다.
- 선택 스테이지의 초기 맵 밀도, 젬 수, 경고 개수를 우측 패널에 미리 표시한다. **[출시 P0]**

권장 행 표현:

```text
> STAGE 06  SOLO 20  COOP 16  12 SEC  ×1.5  HURRY 6  ▲1
```

### 9.2 수치 편집 필드

| 필드 | 범위 | 단위/증분 | 검증·비고 |
|---|---|---|---|
| 스테이지 이름 | 영문/숫자 12자 | 문자 선택 | 현행 읽기 전용, **[운영 P1]** |
| 1인 목표 라인 | 1~999 | 1 | 필수 |
| 협력 목표 라인 | 1~999 | 1 | 1인 목표보다 작으면 경고 |
| 블록 배치 시간 | 3~99 | 1초 | 필수 |
| 점수 배율 | ×0.1~×9.9 | 0.1 | 필수 |
| 클리어 기본 보너스 | 0~999,999 | 100 | 공장 기본 1,000 |
| 시작 카메라 | 0/4/8/12 | 순환 | 맵에 8행 프레임 표시 |
| 잠식 주기 | 0 또는 1~9 | 블록 N개 | 0=끔, 1~2 경고, S6=6·S12=5 공장값 |
| `[ MAP EDIT ]` | — | — | 8×20 편집으로 이동 |
| `[ TEST PLAY ]` | — | — | 검증 후 무료 테스트 |
| `[ RESTORE THIS STAGE ]` | — | — | 해당 스테이지 공장값 작업 사본 생성 |
| `[ SAVE & BACK ]` | — | — | 검증·저장 성공 후 목록 복귀 |

- G로 나가면 작업 사본을 폐기하며 실제 스테이지는 변경하지 않는다.
- 변경된 필드는 `●`, 경고 필드는 `▲`, 오류 필드는 `×`로 표시한다.
- 기본값 복원도 저장 전에는 작업 사본에만 적용한다.

### 9.3 8×20 맵 편집기

- 전체 8×20 그리드를 표시하며 위가 20행, 아래가 1행이다.
- 시작 카메라가 보여주는 8행 영역을 플레이어색 프레임으로 표시한다.
- WASD로 커서를 이동하며 H로 `빈칸(.) → 블록(#) → 젬(*)`을 순환한다.
- 젬은 금색으로 표시한다. 젬 포함 행 제거 시 젬 1개당 `floor(500 × 점수 배율)`을 지급한다.
- G는 수치 편집 화면으로 돌아가며 맵 작업 사본은 유지한다.
- 현재 좌표, 셀 종류, 전체 밀도, 젬 수를 우측 패널에 표시한다. **[출시 P0]**
- `[ CLEAR ROW ]`, `[ COPY ROW ]`, `[ PASTE ROW ]`는 대량 편집용 **[운영 P1]** 기능이다.

### 9.4 저장 검증

| 구분 | 규칙 | 처리 |
|---|---|---|
| 오류 | 시작부터 완성된 8칸 가로 행 존재 | 저장·테스트 불가 |
| 오류 | 7종 블록 중 배치 가능 위치가 없는 블록 존재 | 저장·테스트 불가 |
| 오류 | 목표·시간·배율·보너스·카메라·잠식 범위 초과 | 저장·테스트 불가 |
| 오류 | 맵이 8×20 또는 `.`·`#`·`*` 문자 규격 위반 | 저장·테스트 불가 |
| 경고 | 협력 목표가 1인 목표보다 작음 | 재확인 후 저장 가능 |
| 경고 | 초기 블록 밀도 50% 초과, 젬 포함 | 재확인 후 저장 가능 |
| 경고 | 잠식 주기 1~2 | 재확인 후 저장 가능 |

- 오류가 여러 개면 첫 항목만 토스트로 끝내지 않고 전체 목록을 보여준다. **[출시 P0]**
- 경고 저장 시 H를 2초간 유지한다.
- 저장 전 이전 스테이지 값을 `.bak` 또는 변경 이력에 남긴다.
- 저장 성공 후 스테이지 데이터 버전과 체크섬을 다시 확인한다. **[출시 P0]**

### 9.5 테스트 플레이

- 편집 중인 스테이지 설정을 크레딧 없이 실행한다.
- 검증 통과 시 작업 사본을 테스트 전용 메모리 데이터로 전달한다.
- 테스트 플레이는 유료/이벤트 통계, 랭킹, 크레딧, 정식 플레이 로그에 포함하지 않는다.
- P2 중간 참가와 컨티뉴를 차단한다.
- 클리어·게임 오버·G 2초 유지 시 `ADMIN > STAGE EDIT`로 복귀한다.
- 테스트 중 들어온 실제 코인 펄스는 유료 크레딧에 정상 적립하고 테스트에는 사용하지 않는다. **[출시 P0]**
- 테스트 결과로 클리어 여부, 소요 시간, 하트 소모, 제거 라인, 배치 횟수를 임시 표시하되 운영 통계에는 합산하지 않는다. **[운영 P1]**

### 9.6 공장값 복원

| 작업 | 범위 | 확인 |
|---|---|---|
| `RESTORE THIS STAGE` | 선택 스테이지 | 작업 사본 생성 후 SAVE 필요 |
| `RESET ALL STAGES` | 12개 전체 | 대상 요약 + H 2초 유지 + 즉시 저장 |

`RESET ALL STAGES`는 단일 H 입력으로 실행하면 안 된다. 복원 전 `stages.csv.bak`을 보존하고 감사 로그에 이전 데이터 버전과 실행 시각을 남긴다.

## 10. MAINTENANCE — 현장 진단

상용 오락기는 외부 키보드 없이 장애 원인을 좁힐 수 있어야 한다. 아래 항목은 **[출시 P0]**다.

### 10.1 INPUT TEST

| 입력 | 표시 방식 |
|---|---|
| P1/P2 조이스틱 4방향 | 누르는 동안 해당 방향 점등, 동시 반대 방향은 경고 |
| P1/P2 좌·우 버튼 | PRESS/RELEASE와 홀드 시간 표시 |
| P1/P2 START | 입력 횟수와 마지막 입력 시각 |
| COIN | 펄스 길이, 디바운스 결과, 누적 테스트 횟수 |
| SERVICE | 현재 상태 표시, 테스트 종료에는 별도 H 사용 |

- INPUT TEST의 코인 펄스는 테스트 카운터에만 기록할지 실제 크레딧에 넣을지 기기 설정으로 분리한다. 기본값은 **실제 적립**으로 매출 유실을 방지한다.
- 눌린 상태가 5초 이상 지속되면 `STUCK INPUT` 경고를 표시한다.

### 10.2 SOUND TEST

- BGM 샘플, 코인음, 선택/확정/거부음, 게임 주요 효과음을 개별 재생한다.
- 좌/우 채널과 마스터 볼륨을 표시한다.
- 테스트 종료 시 원래 BGM과 볼륨 상태를 복원한다.

### 10.3 DISPLAY TEST

- 1920×1080 해상도, 전체화면, 실제 출력 해상도와 주사율을 표시한다.
- 안전 영역, 그리드, RGB/백색/검정 화면, 폰트 가독성 패턴을 제공한다.
- 테스트 패턴은 30초 후 자동 종료하며 G로 즉시 복귀한다.

### 10.4 SERIAL I/O TEST

- 포트, 연결 상태, 보드 펌웨어 버전, 마지막 패킷 시각을 표시한다.
- 수신 입력 코드와 디바운스 결과를 실시간 표시한다.
- 연결 해제 시 1초 간격 재연결을 시도하고 10회 실패 시 `SERVICE REQUIRED`로 전환한다.
- 패킷 원문에 개인정보나 보안 토큰이 없다면 최근 20건만 화면에서 조회한다.
- 포트 선택과 패킷 구조는 보드 제작사 확정 후 별도 Serial 명세로 고정한다. **[보류]**

### 10.5 STORAGE TEST

- 실제 저장 경로, 남은 디스크 공간, 마지막 성공 저장 시각, 마지막 백업 시각을 표시한다.
- 임시 파일 쓰기→읽기→삭제 테스트로 쓰기 권한을 검사한다.
- `settings.csv`, `stats.csv`, `stages.csv`의 스키마·체크섬·행 수를 검사한다.
- 손상 시 본 파일을 격리하고 `.bak` 복구 여부를 관리자에게 보고한다.

### 10.6 SYSTEM ACTIONS

| 작업 | 정책 |
|---|---|
| `RESTART GAME` | H 2초 유지, 저장 완료 후 앱 재실행 |
| `REBOOT MACHINE` | H 3초 유지, 출시 OS 권한 구성 필요 |
| `SHUTDOWN MACHINE` | H 3초 유지, 영업 종료용 |
| `RETURN TO GAME` | 저장 완료 후 메인 복귀 |

재부팅·종료는 현재 유료 크레딧 잔액이 있으면 잔액 경고를 먼저 표시한다.

### 11.3 안전 쓰기

1. 새 내용을 `.tmp`에 기록한다.
2. 기록 완료와 스키마를 검증한다.
3. 기존 본 파일을 `.bak`으로 이동한다.
4. `.tmp`를 본 파일명으로 변경한다.

### 11.5 날짜 롤오버

- 프로그램 실행, 게임 시작, 관리자 진입, 통계 초기화 시 OS 로컬 날짜를 확인한다.
- 저장 날짜와 오늘이 다르면 오늘 유료/이벤트 플레이와 오늘 이벤트 사용량을 0으로 초기화한다. **[구현]**
- OS 시간이 24시간 이상 과거로 이동하거나 한 영업일에 두 번 롤오버되면 `CLOCK CHANGED` 감사 로그와 경고를 남긴다. **[출시 P0]**
- 시스템 날짜·시간은 관리자 페이지에서 읽기 전용이다.

### 11.6 내보내기와 개인정보

- USB 내보내기는 로그를 읽기 전용 복사하고 원본을 삭제하지 않는다. **[운영 P1]**
- 본 게임은 이름 4자리 랭킹 외 개인정보를 수집하지 않는다.
- 로그에는 입력한 랭킹 이름을 넣지 않고 세션 식별자만 사용한다.
- 내보내기 성공 시 파일 수, 기간, 대상 경로를 표시하고 감사 로그를 남긴다.

## 12. 오류 처리와 자동 복구

### 12.1 치명 오류

```text
치명 오류
  → 날짜별 오류 로그 기록
  → SYSTEM ERROR 표시
  → 5초 후 자동 재실행

60초 안에 3회 치명 오류
  → 자동 재실행 중지
  → SERVICE REQUIRED
```

위 자동 복구 흐름은 Electron Main Process에 구현되어 있다.

### 12.2 관리자 화면 오류 상태

| 오류 | 사용자 메시지 | 허용 행동 |
|---|---|---|
| 설정 저장 실패 | `SAVE FAILED · 저장 경로 확인` | 재시도, 저장소 테스트, 취소 |
| CSV 손상·백업 복구 성공 | `BACKUP RESTORED` | 내용 확인 후 계속 |
| CSV와 백업 모두 손상 | `FACTORY DATA LOADED` | 진단, 내보내기, 제한 운영 |
| Serial 연결 해제 | `I/O DISCONNECTED` | 재연결, I/O 테스트 |
| 코인 입력 고정 | `COIN INPUT STUCK` | 입력 테스트, 서비스 요청 |
| 디스크 공간 부족 | `STORAGE LOW` | 로그 내보내기/정리, 플레이 차단 기준 확인 |
| 시간 변경 감지 | `CLOCK CHANGED` | 시간 확인, 감사 로그 조회 |

오류 메시지는 문제, 영향, 다음 행동의 세 요소를 포함해야 한다. 예: `SAVE FAILED · 변경 미적용 · H 재시도 / G 취소`.

### 12.3 유료 플레이 차단 기준

다음 상태에서는 메인으로 복귀하더라도 유료 게임 시작을 차단한다.

- Serial I/O가 연결되지 않아 코인·조작 입력을 신뢰할 수 없음
- 설정·통계 파일을 어떤 백엔드에도 저장할 수 없음
- 60초 내 치명 오류 3회 발생
- 유료 크레딧 차감 로그 기록 실패가 반복됨

이미 들어온 유료 크레딧은 화면과 메모리에 유지하고, 복구 후 사용할 수 있도록 우선 저장한다.

## 13. 위험 작업 공통 규칙

| 위험도 | 예시 | 확인 방식 |
|---|---|---|
| 낮음 | 볼륨, 하트, C 변경 | 즉시 변경 + 자동 저장 + 토스트 |
| 중간 | 이벤트 크레딧 지급, 단일 스테이지 복원 | 변경 전/후 표시 + H 확정 |
| 높음 | 통계 초기화, 전체 스테이지 복원, 앱 재시작 | 별도 화면 + H 2초 유지 + 백업 |
| 치명 | 기기 재부팅/종료, 공장 전체 초기화 | 별도 화면 + H 3초 유지 + 잔액 경고 |

- 확인 중 G를 누르거나 다른 행으로 이동하면 확인 상태를 해제한다.
- 확인 상태는 10초 후 자동 취소한다.
- 위험 작업 실행 중에는 추가 입력을 잠그고 진행 상태를 표시한다.
- 성공/실패 모두 감사 로그에 기록한다.
- 공장 전체 초기화는 일반 메뉴에 노출하지 않고 정비 하위 메뉴에 둔다. **[출시 P0]**

## 14. 업주 운영 시나리오

### 14.1 영업 시작 점검 — 목표 3분

1. SERVICE 키로 진입한다.
2. OVERVIEW가 `READY`인지 확인한다.
3. 오늘 통계가 0이고 날짜·시간이 맞는지 확인한다.
4. INPUT TEST에서 코인, P1/P2 START, 주요 버튼을 확인한다.
5. SOUND TEST에서 코인음과 좌/우 출력만 확인한다.
6. `EXIT & SAVE`로 메인 화면과 크레딧 표시를 확인한다.

### 14.2 이벤트 크레딧 지급

1. `SALES & CREDITS > EVENT CREDIT GRANT`로 이동한다.
2. 지급 전 잔액을 확인하고 H로 필요한 수량만 지급한다.
3. 최대 5개 제한과 누적 지급량 증가를 확인한다.
4. 메인으로 복귀해 `EVENT` 잔액을 확인한다.

### 14.3 난이도 조정

1. 조정 전 스테이지 운영 지표를 확인한다.
2. `STAGE SETTINGS`에서 목표·시간·맵을 작업 사본으로 수정한다.
3. 오류·경고 목록을 확인한다.
4. `TEST PLAY`로 최소 3회 검증한다.
5. `SAVE & BACK` 후 데이터 버전과 저장 시각을 기록한다.
6. 정식 플레이 로그에서 변경 전/후 클리어율을 비교한다.

### 14.4 장애 대응

1. OVERVIEW에서 오류 영역과 마지막 발생 시각을 확인한다.
2. 입력, Serial, 저장소 중 빨간 항목의 전용 테스트를 실행한다.
3. 저장소 오류면 로그와 백업을 먼저 보존한다.
4. `RESTART GAME`은 저장 성공을 확인한 뒤 실행한다.
5. 60초 내 3회 재발하면 자동 재시작을 반복하지 않고 `SERVICE REQUIRED` 상태를 유지한다.

### 14.5 영업 종료

1. 오늘 플레이·코인 펄스·이벤트 사용량을 확인한다.
2. 필요한 경우 USB로 로그를 내보낸다.
3. 유료/이벤트 잔액을 확인한다.
4. `SHUTDOWN MACHINE`에서 잔액 경고와 저장 성공을 확인한다.

## 19. 출시 전 확정이 필요한 외부 항목

| 항목 | 필요한 결정 | 영향 |
|---|---|---|
| Serial I/O 보드 | 포트, 패킷, 입력 코드, 펄스, 디바운스, 재연결 | SERVICE/COIN/조작 전체 |
| 물리 관리자 키 | 단발/토글 신호, 코인 도어 위치 | 접근 보안 |
| 코인 단가 | 펄스당 크레딧과 통화 표시 | 매출 추정 |
| Ubuntu 24.04 | X11/Wayland, 자동 실행, 절전, OS 종료 권한 | 키오스크 운영 |
| 로그 내보내기 | USB 자동 탐지, 파일 형식, 보존 책임 | 현장 데이터 회수 |
| 관리자 PIN | 사용 여부, 초기 PIN, 분실 복구 | 역할 분리 |

이 항목은 핵심 관리자 기능을 생략하는 근거가 아니다. 외부 사양이 정해지기 전에는 어댑터 인터페이스와 오류 상태까지 구현하고 실제 값만 교체할 수 있게 한다.
